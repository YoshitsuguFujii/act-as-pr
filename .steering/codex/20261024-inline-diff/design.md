# 設計

## 実装アプローチ
Git の hunk にある連続した削除行・追加行を順に対応付ける。共通の先頭・末尾を除いた中間部分を文字単位の最長共通部分列で比較し、中間部分の組み合わせが 10,000 セルを超える場合は中間部分全体を変更範囲にする。差分テキストはテンプレートの通常のエスケープを通す。ブラウザの構文色付けは行全体を判定してから変更範囲を重ね、文字列やコメントの色を維持する。

## 変更するコンポーネント
- `main.go`: 行内の変更範囲を保持し、hunk の行を対応付ける。
- `viewer.html` / `viewer.css` / `viewer.js`: Unified と Split の変更範囲を描画し、構文色付けを重ねる。
- `main_test.go`: 表示結果と安全性を検証する。
- `viewer_browser_test.go`: 実ブラウザで表示を確認する。
- `README.md`: 表示機能を説明する。

## データ構造
`Line` に表示用の文字範囲を追加する。Git の patch と既存の行番号・行数は変更しない。

## 影響範囲
共通差分テンプレートを使う Files changed、All changes、Commits の表示に及ぶ。ブラウザ内の状態保存、Git 読み取り、watch 通知の形式は維持する。計算量の上限と既存の HTML 出力上限を守る。
